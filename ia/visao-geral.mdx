## Documentação em formato para IA

Toda página desta documentação também existe em Markdown limpo, sem menu nem layout:

| Recurso | Endereço | Uso |
| - | - | - |
| Página em Markdown | adicione `.md` ao fim da URL, ex.: `/integrar/webhooks.md` | colar uma página no chat |
| Índice | `/llms.txt` | lista de todas as páginas com descrição |
| Documentação inteira | `/llms-full.txt` | todo o conteúdo num arquivo só |
| Especificação da API | [`/openapi.json`](/openapi.json) | gerar cliente tipado ou dar ao agente os campos exatos |
| MCP | `/mcp` | pesquisa ao vivo pelo agente |

No topo de cada página, o menu **Copiar página** copia o Markdown ou abre a página direto no ChatGPT, no Claude, no Perplexity, no Cursor ou no VS Code.

## Caminho recomendado

<Steps>
  <Step title="Conecte o MCP">
    Assim o agente consulta a documentação em vez de adivinhar. Veja [Servidor MCP](/ia/mcp).
  </Step>
  <Step title="Adicione as regras ao projeto">
    Cole o bloco de [Regras para o projeto](/ia/regras) no `AGENTS.md` (ou `CLAUDE.md`, `.cursor/rules`).
  </Step>
  <Step title="Use um prompt pronto">
    Escolha a tarefa em [Prompts prontos](/ia/prompts) e cole no agente.
  </Step>
  <Step title="Revise o que é crítico">
    Antes de ir para produção, revise você mesmo três pontos: a chave fica só no servidor, a assinatura do webhook é verificada com o corpo cru e o pedido só é liberado por `payment.succeeded`.
  </Step>
</Steps>

<Warning>
  Nunca cole a sua chave de API ou o segredo do webhook no chat de um agente. Deixe os valores em variáveis de ambiente e diga ao agente só o **nome** da variável.
</Warning>
